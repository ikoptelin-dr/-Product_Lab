# 08. Заказы: резерв, закупка, кабинет сборщика, этикетки, сдача

Когда: после шага 07 и **после договорённости с поставщиком**, кто печатает этикетку и сдаёт посылку. Впишите это в промпт.

```text
Шаг 08 проекта ozon-marketplace: обработка FBS-заказов.
Договорённость с поставщиком: <впиши: кто печатает этикетку, кто упаковывает, куда сдаёт (ПВЗ/СЦ/курьер), время отсечки,
срок сборки в часах>.

Прочитай ozon-marketplace/CLAUDE.md и STATUS.md. Справочник — разделы 2.2, 2.4, 2.5, 3.2, 4.6 отчёта ChatGPT и
«Проверки, которые реально нужны» в конце раздела 7.

1. Приём отправлений: push-уведомления (/v1/notification/*, если доступны) сохраняются в inbox до ответа; резервный опрос
   /v4/posting/fbs/unfulfilled/list раз в 30–60 секунд с полной пагинацией; детали — /v3/posting/fbs/get. Дедупликация
   по номеру отправления и состоянию. Сверить схемы с документацией.
2. Машина состояний: received → checking → reserve_pending → reserved → picking → packed → ready_for_handover →
   handed_over → accepted_by_ozon → delivered; параллельно cancel_pending, exception, return_in_progress.
   Статусы Озона и поставщика хранятся отдельно от внутренних. Терминальные статусы не откатываются старым событием.
3. Маршрутизация: сначала жёсткие ограничения (точная деталь, склад и способ отправки, успеваем к сроку, цена подтверждена),
   потом стоимость. На пилоте один маршрут, но код — под несколько.
4. Закупка у поставщика через outbox: наш референс в заказе; таймаут = «неизвестно» → поиск по референсу → только потом
   повтор. Без возможности поиска — задача оператору, не повтор. Реализуй создание заказа в адаптере поставщика.
5. Кабинет сборщика (страница для поставщика, доступ по отдельному ключу, видит только свои задания): список заданий
   с дедлайном, состав, скан товара, кнопка «собрано» → система вызывает подтверждение сборки в Озоне (/v4/posting/fbs/ship
   — сверить) → получает этикетку (актуальный метод с учётом scanit — сверить) → печать → скан связки «товар–отправление»
   → «сдано».
6. Контроль сроков: для каждого отправления — остаток времени до дедлайна; тревога при нехватке.
7. Отмены: до резерва, после резерва (освободить у поставщика), после упаковки (остановить сдачу), после сдачи (возврат).
8. Тесты — все сценарии из раздела «Проверки» отчёта: дубль push, пропущенное событие, таймаут после успешной закупки,
   частичный резерв, отмена во время сборки, внезапное обнуление, скачок цены, выходной поставщика, неправильная этикетка,
   разделённое отправление.

Живые вызовы, которые меняют состояние заказа на Озоне или создают закупку, — только с флагом конфигурации, который
включаю я.

В конце: STATUS.md, коммит, пуш. Ответь: какие сценарии проходят, что осталось непроверенным вживую, инструкция для
сборщика поставщика на одну страницу (положи в 04-development/packer-guide.md).
```
