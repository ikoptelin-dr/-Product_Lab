# 03. Адаптер поставщика и загрузка прайса

Когда: выбран поставщик пилота и есть его документация. Впишите имя поставщика в первую строку промпта.
Нужны переменные `SUPPLIER_API_LOGIN`, `SUPPLIER_API_KEY` и доступ к домену API поставщика.
Если у поставщика только прайс-файл — положите пример в `04-development/supplier-samples/` (без цен, если это секрет).

```text
Шаг 03 проекта ozon-marketplace: адаптер поставщика <ИМЯ: Rossko / Шате-М / другой>.

Прочитай ozon-marketplace/CLAUDE.md и STATUS.md. Справочник — разделы 3 и 4.2, 4.4, 4.5 отчёта ChatGPT.

1. Проверь доступ к API поставщика и переменные окружения (значения не выводи). Если документация доступна — работай
   по ней, а не по отчёту. Для Rossko в отчёте: SOAP API 2.1, GetCheckout, GetOrders, лимиты 300/мин и 100 000/сутки.
   Для Шате-М: WebApi 1.4, POST /api/v1/orders/byPriceItems, лимиты 2 000 за 15 минут и 120 000 в сутки.
2. В service/suppliers/ сделай общий интерфейс адаптера (загрузить прайс или дельту, проверить наличие по позиции,
   создать заказ, найти заказ по нашему референсу, получить статус) и реализацию для этого поставщика.
   На этом шаге реализуй только чтение: прайс, наличие, поиск заказа. Создание заказа — заглушка с NotImplementedError.
3. Загрузка прайса: сохранить сырой снимок с хешем; определить тип (полный или дельта); проверить полноту (число строк
   против прошлого снимка, обязательные колонки); неполный снимок — в карантин, старые данные не трогать.
4. Нормализация: канонический бренд через справочник синонимов (новые синонимы — в очередь на утверждение, не автоматически),
   артикул: исходный + нормализованный (без пробелов и дефисов, ведущие нули сохраняются), проверка коллизий.
   Семантика остатка: точное число, «больше N», «под заказ» — разные значения, не превращай их в одно число.
5. Запиши в supplier_offer: цену закупки в копейках, НДС, тип остатка, кратность, срок, observed_at.
6. Тесты: повторная загрузка того же файла — без дублей; файл на 40% короче обычного — карантин; «>10» не становится 10
   без пометки; артикул «0451103316» не теряет ноль.
7. Посчитай по лимитам поставщика: как часто реально можно обновлять 500, 5 000 и 40 000 позиций. Запиши в STATUS.md.

В конце: STATUS.md, коммит, пуш. Ответь: что работает вживую, что на примерах, сколько позиций загружено, что спросить
у поставщика.
```
