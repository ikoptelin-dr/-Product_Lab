# Пайплайн разработки

Как я (Claude Code) буду строить систему. Каждый шаг — отдельный промпт из `prompts/`. Вы вставляете его в новую сессию
Claude Code на этом репозитории, я делаю шаг, коммичу в ветку, отчитываюсь, что сделано и что проверить.
Общие правила кода лежат в `ozon-marketplace/CLAUDE.md`, их подхватывает каждая сессия автоматически.

Код живёт в `ozon-marketplace/service/`.

## Карта шагов

```
        ┌─ 00 Разбор данных Максима (как только будет выгрузка)
        │
 Этап 0 ┤  01 Каркас и модель данных
        │  02 Адаптер Озона: чтение (категории, атрибуты, лимиты, товары)
        │  03 Адаптер поставщика и загрузка прайса
        │
 Этап 1 ┤  04 Мастер-каталог и сопоставление артикулов
 пилот  │  05 Генератор карточек (LLM-черновики + валидатор)
 100    │  06 Цена и юнит-экономика
        │  07 Доступность и синхронизация остатков
        │  08 Заказы: резерв, закупка, кабинет сборщика, этикетки, сдача
        │  09 Финансы и сверка
        │  10 Мониторинг и панель
        │
 Этап 2 ┤  11 LLM-помощники: вопросы покупателей, возвраты, расхождения
 500–1к │  второй поставщик (повтор 03 с другим адаптером)
        │
 Всегда ┤  90 Еженедельный обзор: метрики, изменения API Озона, аудит автоматизации
```

## Шаги подробно

| # | Шаг | Что нужно до старта | Результат | Как проверить |
|---|---|---|---|---|
| 00 | Разбор данных Максима | Выгрузка за 3–6 мес. в `04-development/partner-data/` (папку **не коммитим**, она в `.gitignore`) | Реальная экономика на карточку и заказ, доля хвоста и хитов, возвраты, отмены | Цифры сходятся с выплатами Озона |
| 01 | Каркас и модель данных | — | Проект на Python, PostgreSQL, миграции, таблицы из раздела 4.3 отчёта ChatGPT, тесты | `pytest` зелёный, миграции накатываются и откатываются |
| 02 | Адаптер Озона, только чтение | Ключ Озона с правами чтения; доступ к домену (или записанные ответы) | Клиент с лимитером и повторами; загрузка дерева категорий, атрибутов, лимитов кабинета, списка товаров | Реальный запрос к кабинету проходит; лимиты кабинета записаны в БД |
| 03 | Адаптер поставщика | Документация и тестовый ключ поставщика | Загрузка прайса, снимки с хешем, проверка полноты, нормализация бренда и артикула | Повторная загрузка не плодит дубли; неполный файл не обнуляет каталог |
| 04 | Каталог и сопоставление | Шаг 03 | Мастер-каталог, синонимы брендов, связи OEM и кроссов отдельно от «та же деталь», очередь спорных случаев | Нет транзитивных склеек; левая и правая детали — разные товары |
| 05 | Генератор карточек | Шаги 02, 04; выбран провайдер LLM | Черновики карточек из утверждённых полей; валидатор по атрибутам Озона; загрузка пакетами и разбор ошибок импорта | 20 карточек проверены человеком, модель не добавила фактов |
| 06 | Цена | Тарифы из кабинета; налоговый режим | Расчёт минимальной цены по формуле из отчёта ChatGPT (4.7), версии тарифов, стоп убыточных товаров | Тесты на примере из отчёта (P_min ≈ 2 357 ₽) |
| 07 | Остатки | Шаги 03, 06 | Формула публикуемого остатка, TTL, лимит экспозиции, раздельные очереди, приоритет обнуления | Устаревший прайс закрывает продажи; обнуление уходит раньше всего остального |
| 08 | Заказы | Договор с поставщиком о сборке | Приём отправлений (push + опрос v4), машина состояний, закупка с защитой от повторов, кабинет сборщика, этикетка, сдача | 14 сценариев из отчёта ChatGPT (раздел «Проверки») проходят на тестах |
| 09 | Финансы и сверка | Образцы УПД; доступ к выписке банка | Загрузка реализации и начислений (accrual), УПД, банка; построчная сверка; очередь расхождений; выгрузка бухгалтеру | ≥99% суммы сопоставлено на тестовом месяце |
| 10 | Мониторинг | Шаги 07–09 | Панель метрик из раздела 7 отчёта ChatGPT, уведомления в Telegram | Аварийное обнуление срабатывает на просроченном фиде |
| 11 | LLM-помощники | Шаги 04, 08, 09 | Черновики ответов на вопросы и отзывы, разбор возвратов, объяснение расхождений; все в режиме «черновик → человек» | Доля принятых без правок черновиков на 50 примерах |
| 90 | Еженедельный обзор | Работающая система | Отчёт: метрики, узкие места, изменения API Озона, предложения | — |

## Порядок с учётом блокеров

Можно начинать **прямо сейчас**, без ответов на вопросы: шаги 01 и 06 (формула цены без реальных тарифов).

Шаги 02 и 03 требуют доступа к API (ключи и сеть, см. `MISSING-INFO.md`). Без них я пишу код по документации и тестирую
на записанных примерах ответов, но про реальную работу ничего не утверждаю, пока не будет живого запроса.

Шаг 08 бессмысленно доводить до конца, пока нет договорённости с поставщиком о сборке под этикетку Озона.

## Как работать со мной по шагам

1. Откройте новую сессию Claude Code на этом репозитории, ветка `claude/modest-mendel-hpbcy2` (или новая, если скажу).
2. Вставьте содержимое нужного файла из `prompts/` целиком.
3. Я делаю шаг, коммичу и отвечаю: что сделано, что проверено, что не удалось, что нужно от вас.
4. Перед следующим шагом посмотрите `ozon-marketplace/STATUS.md` — я веду там журнал готовности.
