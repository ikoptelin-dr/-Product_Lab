**Дата:** 2026-10-27.
**Статус:** тексты и визуальный бриф готовы; интеграция раздела «Кейсы» на сайт — отдельной задачей в `proba-site-v3`.

Это **демонстрационные проекты на вымышленных брендах**. Они показывают ход работы и состав результата. В них нет и не должно появиться цифр продаж, роста, конверсии, отзывов и имён клиентов. Пометка «Демо-проект: бренд вымышленный, показываем ход работы и результат на примере» стоит в лиде каждого кейса — не убирать её ни на сайте, ни в пересылке.

## Как использовать в переписке

- **Одна ссылка — один кейс.** Выбирайте кейс по ситуации клиента, не отправляйте все четыре.
- **Сразу называйте формат:** «Это демо-проект на вымышленном бренде — так выглядит наша работа и то, что вы получите на выходе».
- **Шаблон сообщения:**
  > Чтобы было понятно, как это выглядит на практике: вот демо-проект на вымышленном бренде — [ссылка]. Там по шагам, что мы делаем и какие файлы вы получаете. Для вашего продукта начнём с бесплатной проверки состава — пришлите его, и вернёмся с планом и сметой по строкам.
- **Для кейса 3:** предложите прислать выгрузку из кабинета; в ответ — смета на аудит.
- **Не пишите** «мы сделали для клиента», «у нас был проект», «результат — рост».

## Как использовать на встрече

1. Спросите о ситуации клиента и выберите один кейс.
2. Покажите раздел «Что получает клиент» — это список файлов, которые он будет держать в руках.
3. Пройдите «Что мы сделали» по шагам и на каждом шаге спросите: «Как это сейчас у вас?»
4. Покажите визуал: 3D-рендеры и ролик (кейсы 1, 2, 4), таблицу рисков (кейс 3).
5. Закончите разделом «Сроки»: срок ведомства — по регламенту, срок проекта — после анализа. Следующий шаг — бесплатная проверка состава или выгрузка для аудита.

**Чего не говорить:** что регистрацию или прохождение модерации можно обеспечить; конкретные сроки проекта до анализа; сравнения с другими подрядчиками.

## Когда появится реальный клиент

Реальный кейс публикуем только с **письменного согласия** клиента: на название бренда, изображения, цитаты и любые цифры.

Что заменить в демо-кейсе:

| Блок | Демо сейчас | В реальном кейсе |
|---|---|---|
| Пометка в лиде | «Демо-проект: бренд вымышленный…» | «Проект для [бренд], публикуем с согласия» + дата |
| Бренд и продукт | вымышленные | реальные, с согласованными изображениями |
| Цитаты интервью (кейс 2) | условные | выдержки из реальных интервью, обезличенные, с согласия респондентов |
| Таблица рисков (кейс 3) | условные строки | обезличенные строки из реальной таблицы |
| Юнит-экономика (кейс 4) | переменные без ставок | реальная структура расчёта; конкретные суммы — только с согласия клиента |
| Результат | список артефактов | список артефактов + факты, которые клиент разрешил: дата получения документа, дата запуска карточки |
| Сроки | регламент + «называем после анализа» | фактическая длительность проекта по этапам — если клиент согласен |
| Цифры продаж | нет | только из данных клиента, с его согласия и с периодом; без экстраполяции |

Демо-кейс после этого не удаляем: переносим ниже реального или оставляем для другого сегмента. В `CONTENT-GUIDE.md` (раздел 2.2) запрет на «кейсы» снимаем только для реальных кейсов с согласием.
