# Proba Lab: правила контента и шаблоны ТЗ

**Дата:** 2026-10-27.

**Для кого:** всех, кто пишет тексты сайта — людей и Claude.

**Связанные файлы:**
- `../semantics/SITE-STRUCTURE.md` — какие страницы и фразы;
- `../semantics/wordstat-clustered.csv` — все фразы с частотами;
- `../research/regulatory-docs-factbase.md` и `../research/production-compliance-factbase.md` — единственные источники регуляторных фактов;
- `../../proba-site-v3/src/regulatory/sources.ts` — ключи источников;
- `../../proba-site-v3/REGULATORY_VERIFY.md` — список фраз для сверки.

## 1. Шаблоны ТЗ

### 1.1 ТЗ на страницу услуги

```markdown
# ТЗ: <URL>

| Поле | Значение |
|---|---|
| URL | dokumenty/... |
| Тип | услуга |
| Волна | 1 / 2 / 3 |
| Родитель | хаб |
| Цель страницы | какое решение должен принять посетитель (оставить заявку на …) |
| Кластер | номер и название из wordstat-clustered.csv |
| Интент | коммерческий / смешанный |
| H1 | ≤ 70 символов, главная фраза или близкая форма |
| Title | ≤ 60 символов, главная фраза в начале, «— Proba Lab» в конце, если влезает |
| Description | ≤ 160 символов: результат + 1 факт + CTA, без «лучший» и «гарантия» |

## Фразы (из выгрузки, без изменений)
- Главная: «…» (Т/Б частота)
- Обязательные (в H2/тексте естественно): …
- Дополнительные (по смыслу, не обязательно дословно): …

## Структура
1. Hero: H1, лид про результат для бизнеса (1–2 предложения), CTA.
2. H2 «Когда это нужно» — 3–5 ситуаций клиента.
3. H2 «Когда не подходит» — честно: какой документ нужен вместо.
4. H2 «Что входит» — 4–7 пунктов работы.
5. H2 «Этапы и сроки» — шаги; срок ведомства отдельно от срока проекта.
6. H2 «Что нужно от вас».
7. H2 «Из чего складывается стоимость» — строки сметы; «от X ₽» только из site-prices.json.
8. H2 «Частые ошибки».
9. H2 «Вопросы» — FAQ из выгрузки (5–7).
10. Блок «Что дальше» — мост к маркетингу (этикетка, карточка).
11. Форма с предвыбором задачи.

## FAQ (реальные вопросы из выгрузки)
| Вопрос (как в выгрузке) | Частота | Ответ опирается на |

## Факты и источники
| Факт | Ключ source | Фактбаза, раздел | Статус |
Отдельный список: **НЕТ В ФАКТБАЗАХ — уточнить у партнёра** (на сайт не ставить, пока не подтверждено).

## Нельзя писать
## Внутренние ссылки (3–5, с анкорами)
## CTA (главный и второй)
## Объём
Сколько нужно, чтобы закрыть интент и вопросы; без вступлений и повторов. Ориентир — указать диапазон, не цель.
```

### 1.2 ТЗ на статью

Те же поля. Отличия:

- **Тип:** статья. **Интент:** информационный.
- **Цель:** ответить на вопрос и привести к услуге — ссылкой в первом экране и CTA в конце.
- **Структура:**
  1. H1.
  2. Короткий ответ в 2–3 предложения — сразу, до оглавления.
  3. Оглавление.
  4. H2 по вопросам из выгрузки.
  5. Блок «Когда лучше доверить специалисту» → услуга.
  6. FAQ.
  7. Автор и дата проверки.
- **Автор:** Илья Коптелин, врач, основатель Proba Lab. **Проверка:** специалист по регуляторике Proba Lab, дата сверки.
- **Ссылки на нормы** — по правилам раздела 3.

## 2. Стайлгайд

### 2.1 Голос Proba

- **Говорим как специалист с собеседником:** конкретно, коротко, по делу.
- **Каждый абзац отвечает на вопрос клиента:** что я получу, что нужно от меня, сколько стоит, сколько ждать, как проверить.
- **Глаголы и факты вместо эпитетов.** Не «профессиональная помощь», а «проверим состав по приложению 7 ТР ТС 021 до оплаты испытаний».
- **Честно о границах:** что мы делаем, что решает ведомство, когда наша услуга не нужна.
- **Предложения ≤ 25 слов, абзацы ≤ 4 строк.** Списки — где перечисление.
- **На «вы», без «уважаемые клиенты».** Без восклицательных знаков.

### 2.2 Запрещённые слова и обороты

| Нельзя | Почему | Как писать |
|---|---|---|
| гарантируем, 100 %, без отказов, точно получите | решение принимает ведомство или площадка | «готовим документы так, чтобы снизить риск отказа» |
| быстро, срочно, за 1 день, за 10 дней | сроки зависят от лаборатории и органа | срок ведомства по регламенту + срок проекта по этапам |
| лучший, лидер, №1, уникальный, инновационный, комплексный подход, команда профессионалов, индивидуальный подход | пустые эпитеты | конкретное действие или факт |
| официальный партнёр Роспотребнадзора, аккредитованная компания Proba Lab | неправда: аккредитованы лаборатории, а не мы | «испытания — в лаборатории, аккредитованной в национальной системе аккредитации» |
| лечит, излечивает, от болезни, заменяет лекарство (в любых примерах) | ст. 25 ФЗ «О рекламе» | описывать продукт без лечебных свойств |
| отказное письмо на БАД, декларация вместо СГР | неверно по фактбазе | «для БАД нужен СГР» |
| СГР на 5 лет | неверно по фактбазе | «действует бессрочно, пока продукция выпускается без изменений» (с меткой) |
| наши клиенты, кейсы, отзывы, «помогли 100 компаниям» | реальных кейсов пока нет | не писать до появления реальных с согласия. Исключение — **демо-кейсы** в разделе `kejsy/`: бренд вымышленный, на странице явная пометка «Демо-проект», без цифр продаж, роста и отзывов |
| «под ключ» в тексте | шаблонно | допустимо только в title или H2, если это фраза из выгрузки |

### 2.3 Сроки

Всегда два срока:
1. **Срок ведомства по регламенту** — с меткой источника.
2. **Срок проекта:** «зависит от состава и лаборатории; называем после анализа».

Диапазоны конкурентов на сайт не ставим.

### 2.4 Цены

- Только «от X ₽» из `proba-growth/pricing/site-prices.json`. Цены, которых там нет, — «смету называем после короткого разговора».
- Всегда оговорка: внешние расходы (госпошлина, испытания, экспертиза) — отдельными строками.
- Госпошлину называть строкой сметы без суммы, пока партнёр не подтвердит размер на дату публикации.
- **Без НДС:** формулировка — на странице «Оплата». В текстах услуг не повторять.

### 2.5 Термины

Термин объясняем при первом упоминании, в скобках или следующим предложением:

> СГР (свидетельство о государственной регистрации) — документ единой формы ЕАЭС, без которого БАД нельзя продавать.

Аббревиатуры без расшифровки: только ЕАЭС, ТН ВЭД, ИНН.

### 2.6 Ссылки на нормы

- Название и номер: «ТР ТС 021/2011», «ст. 10 ТР ТС 021/2011», «ст. 11.1 закона о торговле (в ред. 290-ФЗ)».
- Каждая такая фраза — с меткой источника (раздел 3).
- Без цитат длиннее одной фразы и без гиперссылок на сомнительные агрегаторы. Ссылки только на официальные ресурсы, и только после сверки адреса.
- Дату редакции указываем, если она есть в фактбазе.

### 2.7 Стоп-лист категорий

Не упоминаем как свою услугу и не используем в примерах:
- лекарственные средства и GMP для лекарств;
- медицинские изделия;
- клиническое (энтеральное, парентеральное) питание;
- антисептики;
- раневые покрытия;
- стомийные, урологические, инфузионные и хирургические изделия.

На страницах GMP и хаба «Документы» — строка: «Не работаем с лекарственными средствами и медицинскими изделиями».

## 3. Правила фактов

1. **Источник регуляторных фактов — только фактбазы** (`regulatory-docs-factbase.md`, `production-compliance-factbase.md`). Для коммерческих фактов о Proba — `site-prices.json` и решения владельца.
2. **Метка факта.** Каждая фраза с цифрой, датой, номером закона, регламента, ГОСТа или статьи, а также любое утверждение о требованиях пишется в разметке `⟪ключ|фраза⟫`. Ключ — из `sources.ts`. Если ключа нет, предложить новый в ТЗ (раздел «Новые ключи»), с адресом и разделом фактбазы. При сборке такие фразы автоматически попадают в `REGULATORY_VERIFY.md`.
3. **Метки фактбаз:**
   - **[Гипотеза]** на сайт не идёт;
   - **[Наблюдение — сайт компании]** (цены и сроки конкурентов) на сайт не идёт;
   - **[Наблюдение — по выдаче]** и **[Факт, по выдаче]** — можно, с меткой и статусом «проверить у партнёра».
4. **Чего нет в фактбазе** — в ТЗ раздел «НЕТ В ФАКТБАЗАХ — уточнить у партнёра». На сайт не ставится или пишется без конкретики: «срок уточняем при расчёте».
5. **Ничего не выдумываем:** кейсы, отзывы, клиентов, статистику, проценты отказов, «средние сроки», имена сотрудников, цены конкурентов.
6. **Цифры из Вордстата** в тексты не ставим: это данные для нас, а не для клиента.
7. **Перед публикацией в интернете** партнёр проверяет все фразы новой волны в `REGULATORY_VERIFY.md` и ставит статус в `sources.ts`.

## 4. Чек-лист перед сборкой

**Семантика**
- [ ] Главная фраза — в title, H1 или лиде, без искажения смысла.
- [ ] Обязательные фразы из ТЗ встречаются естественно, без переспама: одна фраза не чаще 2–3 раз.
- [ ] Нет фраз чужого кластера (см. «Спорные пары» в SITE-STRUCTURE.md).

**Метаданные**
- [ ] Title ≤ 60 символов, description ≤ 160, оба уникальны.
- [ ] Один H1. H2 и H3 по порядку.

**Факты**
- [ ] Каждая фраза с цифрой, датой или нормой — в `⟪ключ|…⟫`.
- [ ] Ни одной [Гипотезы] и ни одной цены конкурента.
- [ ] Раздел «НЕТ В ФАКТБАЗАХ» заполнен, и эти факты не попали в текст.

**Честность и стиль**
- [ ] Нет слов из списка 2.2.
- [ ] Нет обещаний результата и сроков ведомства.
- [ ] Нет стоп-листа категорий.
- [ ] Нет выдуманных кейсов, отзывов, клиентов, статистики.
- [ ] Термины объяснены при первом упоминании.

**Польза и конверсия**
- [ ] Первый экран отвечает: что это, кому, следующий шаг.
- [ ] FAQ — вопросы из выгрузки, ответы короткие и по фактбазе.
- [ ] 3–5 внутренних ссылок по ТЗ, анкоры естественные.
- [ ] CTA главный и второй, форма с предвыбором задачи.
- [ ] Блок «Что дальше» ведёт к этикетке и карточке, где уместно.

**Объём**
- [ ] Нет вступлений «В современном мире…», нет повторов, каждый блок можно убрать только с потерей смысла.

**Оформление**
- [ ] Frontmatter: title, description, h1, url, cluster, type, updated.
- [ ] После текста: самопроверка по чек-листу и «Факты для партнёра».
