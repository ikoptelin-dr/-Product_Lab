## 2. Форма «Карты документов» и приёмник заявок — ПОДТВЕРЖДЕНО ЧАСТИЧНО (код работает, конфиг развёртывания не обновлён)

Схема стенда: прокси как nginx (статика + `POST /lead`) → `form-endpoint.mjs` (`env -i`, `TG_API` на заглушку `:8884`).

**В браузере, через прокси (`t2.mjs`):**

| Сценарий | Результат |
|---|---|
| «Карта» без файла | `/spasibo.html` |
| «Карта» с файлом «Состав магний.pdf» | `/spasibo.html` |
| `kontakty #pf-form` | `application/x-www-form-urlencoded` → `/spasibo.html` |

- В журнале и в заглушке Telegram кириллица без искажений: «Магний B6, таблетки «тест»», «пиридоксин — 2 мг». Файл пришёл через `sendDocument` с `filename="Состав магний.pdf"`.
- Файл 4,9 МБ (`curl`) дошёл в заглушку побайтно: sha256 `13b2cee2…` совпадает.

**Проверки в браузере (клиентские):**
- нет согласия и контакт `abc` → «Укажите email, телефон или Telegram (@ник)», «Нужно согласие на обработку данных»;
- файл 6 МБ → «Файл больше 5 МБ — впишите состав…».

Ни в одном из этих случаев запрос не уходит.

**Отказы приёмника.** Клиентская проверка обходилась нативным `form.submit()` в Chromium:

| Случай | Ответ приёмника |
|---|---|
| нет согласия | 400, «Нужно согласие на обработку данных» |
| неверный контакт | 400, «Проверьте контакт» |
| файл 8 МБ | 413, «Слишком большой файл» |

- Во всех трёх случаях `document.characterSet=UTF-8`, `Content-Type: text/html; charset=utf-8`, искажённых символов (Ð/Ñ) нет.
- Ссылки: «Вернуться к форме → /dokumenty/karta-dokumentov.html», «Контакты».
- Axe: 0 нарушений. Скриншот: `qa3/server_noconsent.png`.
- После «Назад» статус формы пустой («Отправляем…» не остаётся).

**Приёмник выключен.** Прокси отдаёт 502 Bad Gateway: это не успех. После «Назад» статус пустой.

**Нет ни журнала, ни Telegram** (`curl` на отдельный экземпляр, `LEAD_LOG=/nonexistent/x.jsonl`):

| Журнал | Telegram | Ответ |
|---|---|---|
| нет | не настроен | 502 «Заявка не отправлена» |
| нет | заглушка отвечает 500 | 502 |
| нет | порт закрыт | 502 |
| нет | работает | 303 |
| есть | ошибка 500 | 303 (так задумано), в stderr «сохранена в журнале» |

**Прочее (`curl`):**
- `text/plain` → 415, GET → 404;
- urlencoded 70 КБ → 413 с заголовком «Слишком большой файл» (текст про файл, хотя файла нет — неточность);
- multipart с пустым полем файла → 303.

**НАХОДКИ:**
- **(серьёзно)** В `deploy/nginx.conf` для `location = /lead` по-прежнему `client_max_body_size 64k`.
  - Проверено на прокси с пределом 64 КБ: «Карта» с файлом 200 КБ в Chromium дала 413 Request Entity Too Large в оформлении nginx, на английском, `characterSet=windows-1252`.
  - В проде любой файл больше ~64 КБ не дойдёт до приёмника, и посетитель увидит не страницу сайта.
  - Нужно `client_max_body_size 6m` (или около того) для `/lead`. Возможно, ещё `error_page` для 413/502/504.
- **(средне, было и раньше)** У `fetch` в Telegram нет тайм-аута.
  - Проверено: заглушка, которая не отвечает. Заявка записана в журнал, но ответа нет и через 8 с (`curl -m 8` → 000).
  - За nginx посетитель через 60 с получит 504 и, скорее всего, отправит форму повторно. Нужен `AbortSignal.timeout(…)`.
- **(мелко)** Если `sendMessage` прошёл, а `sendDocument` нет, функция возвращает `false`. Без журнала ответ будет 502, хотя текст заявки уже в Telegram — посетитель может отправить её ещё раз.
- **(мелко)** В `LABELS` нет полей `production`, `channels`, `details`, `term`: в Telegram они приходят как `channels: Аптеки`.
- **(мелко)** Разбор multipart режет поле на первом вхождении `--boundary` без проверки CRLF. Пример: `--X1x…` в тексте обрезал `composition`. На практике это маловероятно: браузер генерирует случайный разделитель.
