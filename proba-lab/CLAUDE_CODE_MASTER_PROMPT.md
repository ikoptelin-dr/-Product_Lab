## 1. Контекст бизнеса (кратко)

Proba Lab — бюро доказательной коммерциализации health-продуктов из Новосибирска, работает удалённо по всей России. Клиенты — производители и владельцы брендов БАД, специализированного питания, космецевтики, медицинских изделий, биотех-ингредиентов, контрактные производители. ЛПР — собственник/CEO, коммерческий директор, директор по маркетингу.

Ценность: помогаем **доказать, что продукт работает, законно об этом сказать и продать** через врачей, аптеки и маркетплейсы.

Цель сайта — **не показать все навыки, а конвертировать квалифицированного посетителя в заявку.** Главное действие — «Получить мини-разбор» (бесплатно), второе — «Заказать аудит за 90 000 ₽».

Тон: интеллектуальный, сдержанный, точный. Без преувеличений, без «инновационных решений», без псевдонауки.

**Жёсткие запреты:**
- не выдумывать кейсы, отзывы, логотипы клиентов, цифры результатов, адреса, телефоны, реквизиты, имена;
- все неизвестные данные — явные плейсхолдеры из конфигурации (`[[ЗАПОЛНИТЬ: ...]]`), видимые в dev-режиме и блокирующие прод-сборку проверкой (см. п. 9);
- никаких фиктивных API: форма должна реально отправлять данные после настройки переменных окружения.

## 2. Технологии

- **Next.js 15 (App Router)** + **TypeScript (strict)** + **Tailwind CSS v4** (или v3.4, если v4 вызывает проблемы — зафиксируй выбор в README).
- Компоненты — серверные по умолчанию, клиентские только там, где нужна интерактивность (меню, аккордеон, форма, cookie-баннер).
- Валидация — **zod** (общая схема на клиенте и сервере).
- Отправка email — **nodemailer** через SMTP (подходят российские провайдеры: Яндекс 360, Mail.ru для бизнеса, Unisender Go SMTP).
- Шрифты — через `next/font/google`: **Cormorant Garamond** (500, 600; subsets `latin`, `cyrillic`) для заголовков и **Inter** (400, 500, 600; `latin`, `cyrillic`) для текста.
- Иконки — `lucide-react` (тонкие, strokeWidth 1.5), минимально.
- Тесты — **Playwright** (e2e) и **Vitest** (юнит для схемы и обработчика).
- Линтер — ESLint (next config) + Prettier.
- Менеджер пакетов — npm. Node 20+.
- Без тяжёлых UI-библиотек и без framer-motion: анимации на CSS и IntersectionObserver.

## 4. Дизайн-система

**Направление:** интеллектуальный минимализм, архитектурная композиция, много воздуха, строгая типографика. Чёрный, графитовый, белый, сдержанное золото. Никакого шаблонного «AI-оформления»: без градиентов-блобов, неона, glassmorphism, стоковых фото лабораторий, эмодзи-иконок. Логотип основан на архитектурном куполе с восьмилучевой геометрией — используй **только** предоставленные файлы в `/public/brand/`. Если их нет, сделай нейтральную заглушку (правильный восьмиугольник с тонкой линией) и пометь в MISSING_DATA.md. **Не придумывай новый логотип.** Восьмиугольная геометрия допустима как сдержанный графический мотив (маркеры шагов, разделители), но без эзотерики и мистики.

**Токены (CSS-переменные + тема Tailwind):**

```
--color-ink:        #0E0E0E   (основной тёмный / текст)
--color-graphite:   #1F1F1F
--color-graphite-2: #2B2B2B
--color-muted:      #6B6B6B
--color-paper:      #FAFAF7   (фон светлых секций)
--color-white:      #FFFFFF
--color-line:       #E5E2DA   (линии на светлом)
--color-line-dark:  #333333
--color-gold:       #B08D57   (акцент; hover #C6A46C; на тёмном #C9A96E)
```

- Контраст: текст ≥ 4.5:1 (WCAG AA). Золото — только для акцентов, линий и крупных цифр, **не для основного текста на белом.**
- Типографика: H1 clamp(40px → 72px), H2 clamp(30px → 48px), line-height заголовков 1.05–1.15, letter-spacing −0.01em; текст 17–18px / 1.6; цены и номера — `font-variant-numeric: tabular-nums`.
- Сетка: контейнер max-width 1200px, боковые поля 24px (≤640px — 16px), секции padding-block 120px (мобильные 72px).
- Секции чередуют фон: paper / white / ink (тёмные: Offer и Contact).
- Кнопки: primary — фон ink, текст white, hover — золотая нижняя линия 2px; на тёмном фоне primary — фон gold, текст ink. Secondary — контурная 1px. Радиус 2px (архитектурная строгость). Видимый `:focus-visible` (2px gold outline, offset 3px).
- Анимации: появление секций (opacity 0→1, translateY 8px→0, 300 мс, ease-out) через IntersectionObserver. `prefers-reduced-motion: reduce` отключает их полностью.
- Мобильная версия — приоритет: проверить на 360, 390, 768, 1024, 1440px; без горизонтального скролла; tap-цели ≥ 44px; форма удобна одной рукой.

## 6. Серверная обработка заявки (`app/api/lead/route.ts`)

- `runtime = 'nodejs'`. Только POST, `Content-Type: application/json`; тело ≤ 10 КБ.
- Порядок: парсинг → zod-валидация (тот же `lead-schema.ts`) → honeypot (если заполнен — ответить 200 `{ok:true}` и ничего не делать) → time-trap (< 3 c → 400) → rate limit по IP (по умолчанию 5 заявок / 10 мин; IP из `x-forwarded-for`/`x-real-ip`) → (опционально) проверка **Yandex SmartCaptcha** токена на сервере, если задан `SMARTCAPTCHA_SERVER_KEY` → нормализация и экранирование → отправка во все **включённые** каналы параллельно (`Promise.allSettled`).
- Успех = **хотя бы один канал** доставил заявку. Если ни один канал не настроен — в dev логировать заявку в консоль и вернуть 200 с предупреждением в логе; в production вернуть 503 и залогировать ошибку конфигурации (никогда не делать вид, что заявка доставлена).
- Ответы: `200 {ok:true}`, `400 {ok:false, errors}` (по полям), `429 {ok:false, error:'rate_limited'}`, `500/503 {ok:false, error}`. Сообщения пользователю — на русском, без внутренних деталей.
- Логи: без персональных данных в production (только id заявки, каналы, статусы).
- Генерировать `leadId` (crypto.randomUUID) и включать во все уведомления.

**Каналы (включаются наличием env-переменных):**
1. **Email (SMTP, nodemailer):** `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_SECURE`, `LEAD_EMAIL_FROM`, `LEAD_EMAIL_TO` (через запятую). Письмо: тема «Новая заявка Proba Lab — {topic} — {company}», plain-text + простая HTML-таблица (с экранированием). `replyTo` = email заявителя.
2. **Telegram:** `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` → `sendMessage` (HTML parse_mode, экранировать).
3. **Универсальный CRM webhook:** `CRM_WEBHOOK_URL` (+ опционально `CRM_WEBHOOK_SECRET` → заголовок `X-Signature: sha256=HMAC(body)`). JSON-payload: `{ leadId, createdAt, source:'proba-lab-site', utm:{...}, name, company, position, email, contact, topic, category, productUrl, message }`. Таймаут 8 с, 1 повтор.
4. **Bitrix24 (опционально):** `BITRIX24_WEBHOOK_URL` (входящий вебхук) → `crm.lead.add` с маппингом полей (TITLE, NAME, COMPANY_TITLE, POST, EMAIL[{VALUE,VALUE_TYPE:'WORK'}], PHONE, COMMENTS, SOURCE_ID='WEB', UTM_*).
Сделай в README раздел про amoCRM: подключение через универсальный webhook-посредник или через их API (описание, без реализации OAuth).

**UTM:** на клиенте сохранять `utm_*` и `referrer` при первом заходе в sessionStorage (обёрнуто в try/catch) и передавать с заявкой.
