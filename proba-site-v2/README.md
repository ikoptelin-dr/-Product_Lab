# Proba Lab — лендинг (v6)

Путь: бесплатный разбор «Ваш продукт глазами покупателя» → пакет «Предложение для одного продукта» (29 000 ₽) → крупный проект → сопровождение. Для готовых к большой задаче — блок «Какую задачу нужно решить?» с прямым входом в форму. Инженерное направление — отдельное представление «Автоматизация» (адрес `#automation`, возврат «← На главную»).

- `src/data.ts` — **единственное место** для цен (`PRICES`), задач формы (`TASKS`) и отзывов (`REVIEWS`).
- `src/body.html` — разметка и тексты обоих представлений.
- `src/styles.css` — Manrope 600/700 (H1–H3, цены) + Golos Text 400/500/600 (текст, кнопки, формы); петроль #0B5C66, янтарь #B9761C; светлая и тёмная темы.
- `src/app.ts` — меню (с удержанием фокуса), переходы между представлениями, кнопки `data-task` (выбор задачи и прокрутка к форме), режим заявки на пакет, условные поля, локальная проверка форм, движение.
- `scripts/build.mjs` → `dist/proba-lab.html` (самодостаточный файл, логотип встроен один раз через CSS).

```bash
node scripts/build.mjs
```

## Формы — прототип
Проверяют заполнение локально и пишут «Форма заполнена. Отправка пока не подключена». Сетевых запросов и сохранения контактов нет.

## Перед публикацией
1. Подключить отправку форм (почта, CRM или вебхук) и показать честный статус успеха и ошибки.
2. Реальные контакты (запасной способ связи), реквизиты, политика обработки персональных данных и текст согласия.
3. Отзывы — только настоящие согласованные, в `REVIEWS`.
4. Подтвердить состав исполнителей инженерного направления и цену «Разбора одного процесса».

## Раздел «Документы и соответствие» (`dist/dokumenty/`)
Отдельные индексируемые страницы (главная остаётся одним файлом): `index.html` (хаб с квизом «Какой документ нужен»), `registraciya-bad`, `kosmetika`, `deklaracii`, `tu`, `markirovka`, `haccp`, `sanpin`, `gmp`, `laboratorii`, `vyvod-na-rynok`, `kak-my-rabotaem` + общие `section.css` и `section.js`. В шапке и подвале главной — пункт «Документы».

```bash
node scripts/build.mjs          # главная + раздел + REGULATORY_VERIFY.md
node scripts/build-section.mjs  # только раздел
```

- `src/regulatory/pages.ts` — тексты страниц (одна запись на страницу), `quiz.ts` — логика квиза, `render.ts` — шаблон, JSON-LD (BreadcrumbList, FAQPage, Service), `section.css`/`section.ts` — стили и скрипт раздела, `config.ts` — `MAIN_HREF` (адрес главной относительно раздела, по умолчанию `../`) и `SITE_URL` (для canonical/og:url, пока пусто).
- **Факты.** Каждая фраза с цифрой, датой, номером документа или регуляторным утверждением обёрнута в `f(ключ, фраза)`; ключи и адреса источников — в `src/regulatory/sources.ts`. Сборка останавливается, если цифра или номер НПА стоят без метки, и при запрещённых словах или словах из стоп-листа.
- **`REGULATORY_VERIFY.md`** генерируется сборкой: все фразы по страницам с источником, меткой фактбазы и статусом. Это чек-лист для партнёра перед продакшеном; статус меняется в `sources.ts`.
- **`REG_PARTNER`** и **`REG_PRICES`** в `src/data.ts`: реквизиты партнёра выводятся на странице «Как мы работаем», цены «от» — в «Коротко», смете и карточках, **только если заполнены**. Пустые значения ничего не показывают.
- Формы раздела — тот же прототип, что на главной: локальная проверка, статус «Форма заполнена. Отправка пока не подключена.», без сети и хранилища.
