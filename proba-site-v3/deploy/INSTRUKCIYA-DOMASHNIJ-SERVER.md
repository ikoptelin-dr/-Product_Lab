# Как выложить сайт Proba Lab на домашний сервер

Инструкция для того, кто делает это впервые. Команды можно копировать как есть.

**Обозначения:**
- Слова в угловых скобках `<вот так>` — замените своими данными. Скобки не вводите.
- **🖥 Ваш ПК** — компьютер с Windows, за которым вы работаете.
- **🗄 Сервер** — компьютер под столом, на котором будет жить сайт.

---

## 0. Что из чего состоит

| Слово | Что это простыми словами |
|---|---|
| **Сайт** | Просто папка с файлами `.html`, картинками и стилями. Она уже готова и называется `dist`. Ничего «программировать» на сервере не нужно |
| **Сервер** | Компьютер, который круглые сутки включён и отдаёт эти файлы всем, кто открывает сайт |
| **nginx** («энджин-икс») | Бесплатная программа на сервере. Получает запрос «покажи главную» и отдаёт файл `index.html` |
| **Домен** `proba-lab.ru` | Имя сайта. Его покупают у регистратора: reg.ru, nic.ru и др. |
| **IP-адрес** | Номер вашего подключения к интернету, например `95.31.12.34`. Домен через **DNS** указывает на этот номер |
| **Белый IP** | Постоянный адрес, по которому ваш дом можно найти из интернета. **Без него сайт снаружи не откроется** — см. шаг 1 |
| **Проброс портов** | Настройка домашнего роутера: «всё, что пришло на порты 80 и 443, отправляй на сервер» |
| **HTTPS / сертификат** | Замок в адресной строке. Бесплатный сертификат выдаёт Let's Encrypt через программу `certbot` |
| **SSH** | Способ управлять сервером со своего ПК: окно, в которое пишете команды, и они выполняются на сервере |
| **Приёмник заявок** | Маленькая программа (`deploy/form-endpoint.mjs`). Получает заявку с формы и пересылает её вам в Telegram |

**Общий план:**
1. Проверить, что у вас белый IP.
2. Поставить на сервер Ubuntu.
3. Поставить nginx.
4. Скопировать папку сайта.
5. Купить и привязать домен.
6. Пробросить порты на роутере.
7. Включить HTTPS.
8. Подключить заявки в Telegram.

Займёт вечер-два, если делать первый раз.

---

## 1. Сначала главное: есть ли у вас белый IP

Это нужно проверить **до всего остального**. У многих домашних провайдеров адрес «серый» — общий на весь дом или район. Тогда снаружи до вашего компьютера не достучаться, как ни настраивай.

**Как проверить (🖥 Ваш ПК):**
1. Откройте сайт **2ip.ru** и запишите адрес, который он покажет.
2. Зайдите в настройки роутера. Обычно это адрес `192.168.0.1` или `192.168.1.1` в браузере; логин и пароль написаны на наклейке роутера.
3. Найдите раздел «Интернет» или «WAN» и посмотрите там «IP-адрес».
4. Сравните:
   - **совпадают** — у вас, скорее всего, белый IP;
   - **адрес в роутере начинается с `10.`, `100.64`–`100.127`, `172.16`–`172.31` или `192.168.`** — IP серый.

**Если IP серый или меняется** — позвоните провайдеру и попросите «статический белый IP-адрес». Обычно это 100–300 ₽ в месяц.

> **Честное предупреждение про домашний сервер.**
> - Если пропадёт свет или интернет, сайт и приём заявок тоже пропадут.
> - Для теста и старта это нормально.
> - Если со временем станет важно, чтобы сайт работал всегда, можно арендовать VPS (виртуальный сервер) в российском дата-центре: Timeweb, Selectel, REG.RU — от 300–500 ₽ в месяц. Инструкция для VPS почти такая же, начиная с шага 3.

## 2. Поставить на сервер Ubuntu Server

Инструкция написана под **Ubuntu Server 24.04 LTS**. Это бесплатная система для серверов, под неё написаны все команды ниже.

> ⚠️ **Установка сотрёт всё на диске сервера.** Если там что-то нужное — сначала сохраните.
>
> Если на сервере уже стоит Ubuntu или Debian — пропустите этот шаг.
>
> Если на сервере Windows и стирать её нельзя — напишите: под Windows путь другой.

### 2.1. Что скачать (🖥 Ваш ПК)

1. **Образ системы.** На ubuntu.com → Download → Ubuntu Server → **24.04 LTS** скачайте файл `ubuntu-24.04.x-live-server-amd64.iso` (около 3 ГБ).
2. **Rufus** — программа для записи флешки: rufus.ie, файл `rufus-4.x.exe`, установка не нужна.
3. **Флешка** — от 8 ГБ, её содержимое тоже сотрётся.

### 2.2. Записать флешку (🖥 Ваш ПК)

1. Вставьте флешку и запустите Rufus.
2. «Устройство» — ваша флешка. «Выбрать» — скачанный `.iso`.
3. Нажмите «Старт», затем OK на все вопросы. Подождите 5–10 минут.

### 2.3. Установить (🗄 Сервер)

1. Подключите к серверу монитор, клавиатуру и **интернет-кабель**: по кабелю надёжнее, чем по Wi-Fi.
2. Вставьте флешку и включите компьютер.
3. Сразу жмите клавишу выбора загрузки — обычно `F12`, `F11`, `F8` или `Esc`, зависит от материнской платы. Выберите флешку.
4. Дальше на всех экранах — Enter, кроме этих:
   - **Язык** — English: так проще искать ошибки в интернете.
   - **Profile setup** — ваше имя, имя сервера (например `proba`), **имя пользователя** (например `ilya`) и **пароль**. Пароль запишите!
   - **SSH Setup** — поставьте галочку **Install OpenSSH server**. Это обязательно: так вы будете управлять сервером со своего ПК.
   - **Featured server snaps** — ничего не выбирайте.
5. После «Reboot Now» выньте флешку.

### 2.4. Узнать адрес сервера в домашней сети (🗄 Сервер)

1. Войдите своим именем и паролем. При вводе пароля символы не видны — это нормально.
2. Наберите и нажмите Enter:
   ```
   ip -4 addr
   ```
3. Найдите строку `inet 192.168.x.x` — не `127.0.0.1`. Это **локальный адрес сервера**, например `192.168.1.50`. Запишите его.

### 2.5. Закрепить этот адрес за сервером (🖥 Ваш ПК, настройки роутера)

Найдите в роутере раздел «DHCP» → «Резервирование адресов» (бывает «Привязка IP к MAC» или «Статический IP»). Закрепите адрес `192.168.1.50` за сервером: в списке устройств он называется так, как вы назвали сервер.

Зачем: иначе после перезагрузки адрес может смениться, и проброс портов перестанет работать.

> С этого момента монитор и клавиатура серверу не нужны — дальше всё со своего ПК.

## 3. Подключиться к серверу со своего ПК (🖥 Ваш ПК)

В Windows 10 и 11 всё нужное уже есть.

1. Нажмите **Пуск**, наберите **PowerShell** и откройте его.
2. Введите, подставив своё имя пользователя и адрес сервера:
   ```
   ssh ilya@192.168.1.50
   ```
3. На вопрос `Are you sure you want to continue connecting` напишите `yes` и Enter.
4. Введите пароль: символы не видны, это нормально.

Если в начале строки появилось `ilya@proba:~$` — вы **внутри сервера**. Все команды, помеченные **🗄**, вводите в это окно.

Выйти — команда `exit`.

## 4. Подготовить сервер (🗄 Сервер, через окно SSH)

Копируйте по одной строке. `sudo` значит «выполнить от имени администратора» — при первом запуске он спросит ваш пароль.

```bash
sudo apt update && sudo apt upgrade -y
sudo apt install -y nginx nodejs ufw unattended-upgrades
```

- **nginx** раздаёт сайт;
- **nodejs** нужен приёмнику заявок;
- **ufw** — защитный экран (файрвол);
- **unattended-upgrades** сам ставит обновления безопасности.

**Включите файрвол**: разрешить только SSH и сайт, всё остальное закрыть.

```bash
sudo ufw allow OpenSSH
sudo ufw allow 'Nginx Full'
sudo ufw enable
```

На вопрос ответьте `y`.

**Проверка:** откройте на своём ПК браузер и зайдите на `http://192.168.1.50`. Должна быть страница **«Welcome to nginx!»** — значит, nginx работает.

## 5. Скачать сайт с GitHub (🖥 Ваш ПК)

1. Откройте https://github.com/ikoptelin-dr/-Product_Lab/tree/claude/pensive-tesla-1hg10j. Войдите в свой GitHub, если репозиторий закрытый.
2. Нажмите зелёную кнопку **Code** → **Download ZIP**.
3. Распакуйте архив, например на Рабочий стол. Внутри вам нужны **только две папки**:
   - `proba-site-v3\dist` — **сам сайт**;
   - `proba-site-v3\deploy` — настройки сервера и приёмник заявок.

> ⚠️ **Про сборку `dist` на GitHub.** Она собрана **для проверки**:
> - формы заявок там не отправляются — пишут «Отправка пока не подключена»;
> - адреса для поиска (canonical) не прописаны.
>
> Для боевого сайта нужна сборка с адресом `https://proba-lab.ru` и включённым приёмом заявок. Её лучше попросить у Claude: он соберёт её и положит в репозиторий, вы скачаете так же. Сначала можно спокойно пройти всю инструкцию с проверочной сборкой: страницы, кнопки и анимации в ней те же.

## 6. Скопировать сайт на сервер

Проще всего — программой **WinSCP** (🖥 Ваш ПК): это как «Проводник», только для сервера.

1. Скачайте с winscp.net и установите.
2. Запустите. Протокол **SFTP**, «Имя хоста» `192.168.1.50`, ваши имя пользователя и пароль → «Войти».
3. Слева — ваш компьютер, справа — сервер, ваша домашняя папка `/home/ilya`.
4. Перетащите **папку `dist`** слева направо и дождитесь окончания копирования.

**Переложите сайт туда, откуда его берёт nginx** (🗄 Сервер, окно SSH):

```bash
sudo mkdir -p /var/www/proba-lab
sudo rm -rf /var/www/proba-lab/dist
sudo mv ~/dist /var/www/proba-lab/dist
sudo chown -R www-data:www-data /var/www/proba-lab
```

> Без WinSCP можно одной командой в PowerShell (🖥), находясь в папке `proba-site-v3`:
> ```
> scp -r .\dist ilya@192.168.1.50:~/
> ```
> А дальше — те же четыре команды на сервере.

## 7. Настроить nginx под сайт

1. **Скопируйте** через WinSCP файл `proba-site-v3\deploy\nginx.conf` в домашнюю папку на сервере.
2. **Подключите его** (🗄 Сервер):
   ```bash
   sudo cp ~/nginx.conf /etc/nginx/sites-available/proba-lab
   sudo ln -sf /etc/nginx/sites-available/proba-lab /etc/nginx/sites-enabled/proba-lab
   sudo rm -f /etc/nginx/sites-enabled/default
   ```
3. **Впишите домен.** Откройте файл в простом редакторе:
   ```bash
   sudo nano /etc/nginx/sites-available/proba-lab
   ```
   - Найдите строку `server_name _;` (стрелками) и замените на:
     ```
     server_name proba-lab.ru www.proba-lab.ru;
     ```
   - Сохранить — `Ctrl+O`, Enter. Выйти — `Ctrl+X`.
4. **Проверьте настройки и примените:**
   ```bash
   sudo nginx -t
   ```
   Должно быть `syntax is ok` и `test is successful`. Тогда:
   ```bash
   sudo systemctl reload nginx
   ```
5. **Проверка:** на своём ПК откройте `http://192.168.1.50`. Должен открыться **сайт Proba Lab**. Откройте и несуществующий адрес, например `http://192.168.1.50/abc` — должна открыться страница «Страница не найдена».

> **Сайт пока закрыт от Яндекса и Google.** В настройке есть строки `X-Robots-Tag "noindex, nofollow"` — так задумано на время проверки. Когда будете готовы к поиску, их нужно удалить (шаг 11).

## 8. Домен proba-lab.ru: купить и направить на ваш дом

1. **Купить домен** (если ещё не куплен): reg.ru, nic.ru или другой регистратор `.ru`. Около 200–900 ₽ в год. Для `.ru` потребуются паспортные данные — это требование для зоны `.ru`.
2. **Указать адрес.** В личном кабинете регистратора откройте «Управление DNS» («DNS-записи») и добавьте две записи типа **A**:

   | Тип | Имя (хост) | Значение |
   |---|---|---|
   | A | `@` | ваш **белый IP** из шага 1 |
   | A | `www` | тот же белый IP |

3. **Подождать** от 15 минут до нескольких часов, пока запись разойдётся по интернету.

## 9. Пробросить порты на роутере (🖥 настройки роутера)

Найдите раздел **«Переадресация портов»** (бывает «Виртуальные серверы», «Port Forwarding» или «NAT»). Добавьте два правила:

| Внешний порт | Внутренний IP | Внутренний порт | Протокол |
|---|---|---|---|
| 80 | `192.168.1.50` (ваш сервер) | 80 | TCP |
| 443 | `192.168.1.50` | 443 | TCP |

> ⚠️ **Порт 22 (SSH) наружу не пробрасывайте.** Управлять сервером вы будете только из дома, так безопаснее.

**Проверка:** выключите Wi-Fi на телефоне, чтобы зайти через мобильный интернет, и откройте `http://proba-lab.ru`. Должен открыться сайт.

> **Не открывается:**
> - проверьте, белый ли IP (шаг 1) и есть ли запись A (шаг 8);
> - некоторые провайдеры закрывают порт 80 — спросите у них.

## 10. Включить HTTPS — замок в браузере (🗄 Сервер)

Делать **только после** того, как `http://proba-lab.ru` открывается с телефона.

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d proba-lab.ru -d www.proba-lab.ru
```

1. Certbot спросит **email** — для писем об окончании сертификата.
2. Затем согласие с условиями — `Y`. Рассылку можно отклонить — `N`.
3. Он сам впишет сертификат в настройку nginx и включит переадресацию с `http` на `https`.
4. Продлевать сертификат каждые 3 месяца он будет сам.

**Проверка:** `https://proba-lab.ru` открывается с замком.

**Включите строгий HTTPS:**
1. `sudo nano /etc/nginx/sites-available/proba-lab`.
2. Найдите строку
   ```
   # После HTTPS: add_header Strict-Transport-Security "max-age=31536000" always;
   ```
3. Уберите в начале `# После HTTPS: `, чтобы строка начиналась с `add_header`.
4. Сохраните, затем:
   ```bash
   sudo nginx -t && sudo systemctl reload nginx
   ```

## 11. Открыть сайт для поиска — когда будете готовы

Пока не подключены заявки (шаг 12) и не стоит боевая сборка, лучше не открывать.

1. `sudo nano /etc/nginx/sites-available/proba-lab`.
2. Удалите **обе** строки с `X-Robots-Tag` — одна в начале, одна в блоке `/assets/`.
3. Сохраните, затем:
   ```bash
   sudo nginx -t && sudo systemctl reload nginx
   ```
4. Добавьте сайт в **Яндекс Вебмастер** (webmaster.yandex.ru) и подтвердите права.

## 12. Заявки с сайта → в ваш Telegram

### 12.1. Создать бота (телефон)

1. **Создайте бота.** В Telegram найдите **@BotFather** → `/newbot` → придумайте имя, например `Proba Lab заявки`, и логин, который заканчивается на `bot`.
2. **Сохраните токен.** BotFather пришлёт **токен** вида `1234567890:AAH...`. Это пароль от бота: **никому не показывайте и не выкладывайте**.
3. **Напишите боту.** Найдите своего бота и отправьте ему любое сообщение, например «привет».
4. **Узнайте свой chat_id.** Откройте в браузере (вставьте свой токен вместо `<ТОКЕН>`):
   ```
   https://api.telegram.org/bot<ТОКЕН>/getUpdates
   ```
   Найдите `"chat":{"id":123456789` — это число и есть **chat_id**.

### 12.2. Запустить приёмник заявок как службу (🗄 Сервер)

1. **Скопируйте** через WinSCP файл `proba-site-v3\deploy\form-endpoint.mjs` в домашнюю папку на сервере.
2. **Подготовьте папки и журнал заявок:**
   ```bash
   sudo useradd --system --no-create-home proba-leads
   sudo mkdir -p /opt/proba
   sudo cp ~/form-endpoint.mjs /opt/proba/
   sudo touch /var/log/proba-leads.jsonl
   sudo chown proba-leads /var/log/proba-leads.jsonl
   sudo chmod 640 /var/log/proba-leads.jsonl
   ```
3. **Создайте службу**, чтобы приёмник сам запускался после перезагрузки:
   ```bash
   sudo nano /etc/systemd/system/proba-leads.service
   ```
   Вставьте текст, подставив свой токен и chat_id:
   ```ini
   [Unit]
   Description=Proba Lab — приём заявок с сайта
   After=network-online.target

   [Service]
   User=proba-leads
   Environment=TG_TOKEN=<ТОКЕН>
   Environment=TG_CHAT=<CHAT_ID>
   ExecStart=/usr/bin/node /opt/proba/form-endpoint.mjs
   Restart=always

   [Install]
   WantedBy=multi-user.target
   ```
   Сохраните — `Ctrl+O`, Enter, `Ctrl+X`.
4. **Закройте файл службы от чужих глаз** — в нём токен:
   ```bash
   sudo chmod 600 /etc/systemd/system/proba-leads.service
   ```
5. **Запустите:**
   ```bash
   sudo systemctl daemon-reload
   sudo systemctl enable --now proba-leads
   sudo systemctl status proba-leads
   ```
   Должно быть `active (running)`. Выйти из просмотра — клавиша `q`.

### 12.3. Боевая сборка сайта

Чтобы формы начали отправлять заявки, сайт должен быть **собран с адресом приёмника**: `FORM_ENDPOINT=/lead` и `SITE_URL=https://proba-lab.ru`.

Попросите Claude собрать её. Скачайте новую папку `dist` и замените её на сервере так же, как в шаге 6.

### 12.4. Проверка вживую

С телефона отправьте заявку на сайте — по одной с каждой формы, а в «Карте документов» приложите небольшой файл. Должно быть так:
- на сайте — страница **«Заявка отправлена»**;
- в Telegram — **сообщение с заявкой**, для «Карты» — ещё и **файл**;
- в журнале на сервере — две строки на заявку. Посмотреть журнал:
  ```bash
  sudo tail -n 5 /var/log/proba-leads.jsonl
  ```

> ⚖️ **Перед приёмом настоящих заявок** покажите юристу одно место. В «Политике обработки персональных данных» (п. 5.4) написано, что данные за границу не передаются, а заявки уходят через сервис Telegram. Пусть юрист решит, как это оформить.

## 13. Как обновлять сайт потом

Когда в репозитории появилась новая версия:

1. **Скачайте её** (🖥): GitHub → нужная ветка → Code → Download ZIP → распакуйте.
2. **Скопируйте на сервер:** WinSCP, папку `proba-site-v3\dist` в домашнюю папку сервера.
3. **Подмените сайт** (🗄):
   ```bash
   sudo rm -rf /var/www/proba-lab/dist
   sudo mv ~/dist /var/www/proba-lab/dist
   sudo chown -R www-data:www-data /var/www/proba-lab
   ```

Перезапускать nginx не нужно.

## 14. Если что-то не работает

| Что видите | Что проверить |
|---|---|
| `ssh` пишет `Connection refused` / `timed out` | Сервер включён? Адрес из шага 2.4 верный? При установке стояла галочка OpenSSH? |
| `http://192.168.1.50` не открывается | `sudo systemctl status nginx` — должно быть `active (running)`; `sudo ufw status` — должно быть разрешено `Nginx Full` |
| Вместо сайта «Welcome to nginx!» | Не удалили `default` или не подключили `proba-lab` — повторите шаг 7 |
| `nginx -t` пишет ошибку | Опечатка в файле настройки. Ошибка показывает номер строки — исправьте её через `sudo nano …` |
| Дома сайт открывается, с мобильного интернета — нет | Белый IP (шаг 1), записи A (шаг 8), проброс портов 80 и 443 на верный адрес (шаг 9) |
| `certbot` пишет ошибку `Timeout` / `Connection refused` | Порт 80 снаружи не открыт: проверьте шаг 9 и спросите провайдера |
| Форма пишет «Отправка пока не подключена» | Стоит проверочная сборка — нужна боевая (шаг 12.3) |
| После отправки «Заявка не отправлена» или ошибка 502 | `sudo systemctl status proba-leads`; `sudo journalctl -u proba-leads -n 30` — там будет причина |
| Заявка пришла, но без файла | Сайт показал «Заявка принята, файл не дошёл». Файл не прошёл в Telegram: попросите клиента прислать его в ответ |
