# 02. Техническая карта: сайт proba-lab.ru и как собрать на его базе новый

Всё ниже проверено по репозиторию на ветке `claude/pensive-tesla-1hg10j` (13.11.2026).

## 1. Что это за сайт

- **Статический генератор** без фреймворка: TypeScript плюс Markdown → готовый HTML. Сервера-приложения и базы данных нет.
- **Исходники движка:** `proba-site-v3/` (около 3 800 строк TS). **Тексты страниц:** `proba-growth/content/pages/**/*.md` (58 файлов). **Юридические документы:** `proba-legal/*.md`.
- **Готовый сайт:** `proba-site-v3/dist/` — 80 страниц, лежит в репозитории, это боевая сборка.
- **Качество** (проверено 05.11.2026):
  - полная проверка `verify.sh` прошла без ошибок;
  - доступность (axe) — 0 нарушений;
  - PageSpeed — 98 (со слов основателя).

## 2. Как устроен движок

```
proba-site-v3/
  scripts/build.mjs     сборка: Markdown + TS → dist/, sitemap.xml, robots.txt, проверки текстов
  scripts/verify.sh     полная проверка в браузере (Playwright): все страницы × 1440/768/390, ссылки, sitemap, JSON-LD, формы, меню, доступность
  scripts/verify.mjs    сами проверки
  scripts/windows-package.sh  собирает PROBA-SERVER.zip для сервера на Windows
  src/layout.ts         <head>, шапка, подвал, кнопка «Связаться» (телефон, MAX, почта), JSON-LD, типографика
  src/site.css          дизайн-система (тёмная и светлая темы блоков, стекло, анимации, reduced-motion)
  src/site.ts           клиентский скрипт: меню, формы, Метрика после согласия на cookie, события аналитики, квиз, калькулятор, анимации
  src/forms.ts          формы («Обсудить задачу» — короткая: контакт + подробности под спойлером)
  src/data.ts           COMPANY (реквизиты, телефон, почта, MAX), TASKS (варианты задач в форме)
  src/blocks.ts         блоки Markdown-разметки (карточки цен, шаги, FAQ и т. п.)
  src/pages/*.ts        страницы, собранные кодом: главная, компания, цены, блог-хаб, юридические
  src/regulatory/       раздел «Документы» (БАД): квиз, метки источников ⟪ключ|фраза⟫ — для нового сайта НЕ нужен
  deploy/server.mjs     сервер для Windows: отдаёт сайт и принимает заявки POST /lead
  deploy/form-endpoint.mjs  приём заявок → почта (SMTP Яндекса), Битрикс24 (вебхук), Telegram (выключен), копия в журнал (можно выключить)
  deploy/windows/       .bat-файлы управления, upravlenie.ps1, Caddyfile, шаблон nastrojki.txt
```

**Формат страницы в Markdown** (`proba-growth/content/pages/...md`):

```
---
title: "…"            # уникальный, сборка падает на повторе
description: "…"
h1: "…"               # ровно один h1 на странице
url: "razdel/stranica/"
type: "service" | "article" | "case" | "company" | "hub" | "home" | "local" | "tool"
updated: "2026-10-27"
---
Текст. **[Кнопка]** · [ссылка](/razdel/stranica/)
```

## 3. Сборка

```bash
# один раз: зависимости движка (esbuild, playwright) берутся из proba-site/node_modules — в репозитории их нет
cd proba-site && npm install && cd ..

cd proba-site-v3
node scripts/build.mjs                       # проверочная сборка (формы не отправляют)
SITE_URL=https://proba-lab.ru FORM_ENDPOINT=/lead PROD=1 YM_ID=114051584 node scripts/build.mjs   # боевая сборка proba-lab.ru
bash scripts/verify.sh /tmp/shots 8931       # полная проверка (около 20 минут)
bash scripts/windows-package.sh              # пакет для сервера → ../PROBA-SERVER.zip
```

- **Нужен `pandoc`** (`/usr/bin/pandoc`): сборка переводит юридические документы в HTML. Если его нет — `apt-get install -y pandoc`.
- **Путь к esbuild в `build.mjs` абсолютный:** `/home/user/-Product_Lab/proba-site/node_modules/esbuild/...`. Если репозиторий лежит в другом месте, путь надо поправить.
- **Переменные сборки:**
  - `SITE_URL` — домен, без него нет canonical;
  - `FORM_ENDPOINT=/lead` — формы отправляют заявки;
  - `YM_ID` — номер Метрики;
  - `MAX_URL` — заменить ссылку MAX;
  - `PROD=1` — требует `SITE_URL`;
  - `DIST` — собрать в другую папку.

## 4. Встроенные проверки сборки: правила проекта, не ослаблять

Сборка **падает**, если:
- повторяется `title` или на странице не один `h1`;
- остался шаблон `{{` или метка факта `⟪⟫`;
- встретилось запрещённое слово. Списки в `scripts/build.mjs`, около строки 220:
  - `FORBIDDEN` — «инновационный», «уникальный», «комплексный подход», «синергия», «эффективные решения», «под ключ» без кавычек и т. п.;
  - `REG_FORBIDDEN` — для раздела «Документы»: «100%», «лучший», «лечит»…;
  - `STOPLIST` — **категории из стоп-листа основателя** (медизделия работодателя): антисептики, раневые, стомийные, урологические, инфузионные, хирургические, энтеральное и парентеральное, клиническое питание;
- в `site.js` есть `fetch`, `XMLHttpRequest`, `localStorage`, `sessionStorage`, `indexedDB`. **Скрипт сайта ничего не хранит в браузере и не делает своих сетевых запросов** — это обещание посетителям. Метрика грузится отдельным скриптом Яндекса после согласия.

**⚠ Для медицинского агентства `STOPLIST` придётся пересмотреть вместе с основателем.** Слова вроде «хирургический» будут встречаться в текстах про клиники. Но смысл стоп-листа — конфликт с работодателем (медизделия) — остаётся. Решение принимает основатель, а не модель.

## 5. Что переиспользовать для нового сайта

| Берём | Что это |
|---|---|
| Движок сборки, `layout.ts`, `site.css`, `blocks.ts` | дизайн, типографика, мобильная версия, доступность, SEO (canonical, sitemap, JSON-LD, OG) |
| Формы + `deploy/form-endpoint.mjs` + `server.mjs` | заявки на почту и в Битрикс24, проверка контакта, согласие на ПД |
| Метрика после согласия + события в `site.ts` | `form_start`, `form_error`, `form_*`, `cta_click`, `scroll_90`, `contact_click`, `fab_open`, параметр визита `section`, UTM в заявку |
| Кнопка «Связаться» | телефон, MAX, почта |
| Страница кейса (`type: "case"`) | шаблон кейса с пометкой «демо» |
| Блог (`type: "article"`) | статьи с автором, датой, BlogPosting |
| Юридические шаблоны `proba-legal/` | политика ПД, согласие, оферта — **переписать под новые услуги** |
| `verify.sh` / `verify.mjs` | вся проверка качества. Тексты проверок про «Документы» и калькулятор убрать вместе с разделом |

| Убираем | Почему |
|---|---|
| `src/regulatory/`, раздел «Документы», квиз, `REGULATORY_VERIFY.md` | тема БАД |
| Калькулятор юнит-экономики (`calc.ts`, `kalkulyator-…`) | тема маркетплейсов. Оставить, только если основатель решит |
| Прайс `proba-growth/pricing/site-prices.json` и `prices.ts` | заменить прайсом медицинского агентства |
| Тексты `proba-growth/content/pages/` | писать новые. Старые не трогать, если proba-lab.ru остаётся жить |

**Рекомендация предыдущего чата:** не переделывать proba-lab.ru на месте, а сделать копию движка в новую папку, например `med-site/`, со своей папкой текстов. Тогда сайт агентства БАД продолжит работать, его не сломает.

## 6. Сервер и выкладка: важно

- Сайт крутится **на домашнем компьютере основателя с Windows**, папка `D:\proba`. Пошаговая инструкция для него — `INSTRUKCIYA-WINDOWS-SERVER.md` в корне репозитория.
- **Порты 80 и 443 держит Caddy его друга** (папка `C:\JAVA_projects\academy_website\persistent\caddy\`, файл `Caddyfile`). Наш сайт подключён к нему блоком `proba-lab.ru { reverse_proxy 127.0.0.1:8080 }`. Свой Caddy у нас отключён: режим «общий Caddy», файл `OBSHCHIJ-CADDY.txt` в `D:\proba`. **Чужой Caddy не трогать и не останавливать.**
- **Второй сайт на том же компьютере:**
  - отдельная папка, например `D:\med`;
  - в её `nastrojki.txt` — `SITE_PORT=8081`;
  - в Caddyfile друга — блок `новый-домен.ru { reverse_proxy 127.0.0.1:8081 }`;
  - **⚠ имена задач планировщика** в `deploy/windows/upravlenie.ps1` захардкожены («Proba - sajt», «Proba - caddy»). Для второго сайта их нужно сделать другими, иначе установка автозапуска второго сайта перезапишет первый.
- **Секреты** (пароль почты, вебхук Битрикс24) хранятся только на сервере в `nastrojki.txt`. В репозиторий не коммитить, в чат не просить.
- **Обновление сайта у основателя:** скачать `PROBA-SERVER.zip` с GitHub → заменить папку `site`. Если менялся `server.mjs` — заменить его и перезапустить.
- **На настоящем Windows** скрипты из `deploy/windows/` предыдущий чат не мог запустить: проверял их только чтением кода. Ошибки на сервере основатель присылает снимками экрана.
