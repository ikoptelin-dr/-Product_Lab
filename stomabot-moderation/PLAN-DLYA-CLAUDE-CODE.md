# План сборки бота модерации в Claude Code

Как пользоваться: открываете Claude Code в папке `stomabot-moderation/`, копируете задание этапа целиком,
ждёте, пока Claude закончит, проверяете по пункту «Как проверить». Только потом — следующий этап.
Один этап = одна сессия = один коммит.

Если что-то сломалось — пишите Claude Code прямо: «Тест П-4 падает, вот вывод: …».

---

## Этап 0. Подготовка (один раз)

Задание для Claude Code:

```
Прочитай TZ-BOT-MODERACII.md и REGLAMENT-MODERACII.md в этой папке.
Создай файл CLAUDE.md с правилами проекта:
- стек: Python 3.12, FastAPI, Jinja2, SQLite, pytest, без других фреймворков и без сборщиков фронтенда;
- главное правило: текст сообщения, не прошедшего проверку, нельзя сохранять в БД, писать в логи,
  передавать во внешние сервисы или включать в текст исключений;
- никакого ИИ и внешних API для проверки — только правила и списки слов из папки rules/;
- все тексты для пользователей — только в app/texts.py;
- после каждой задачи запускать pytest и показывать результат.
Создай requirements.txt и пустую структуру папок из раздела Б2 ТЗ. Ничего больше не делай.
```

Как проверить: в папке появились `CLAUDE.md`, `requirements.txt`, папки `app/`, `rules/`, `tests/`.

## Этап 1. Модуль проверки

```
Сделай app/normalize.py и app/checker.py по разделам А4 и Б3 ТЗ.
Заполни стартовые списки в rules/ (ostroe.txt, emocii.txt, lichnye-dannye.txt, imena.txt,
prodazha.txt, razreshennye-domeny.txt). В lekarstva.txt положи 30 самых распространённых
в России торговых названий и МНН как пример — финальный список утвердит юротдел.
Списки читаются из файлов при старте, в коде слов быть не должно.
Напиши tests/test_checker.py: минимум по 5 примеров «должно блокировать» на каждую категорию
и 15 примеров «не должно блокировать» («больше», «кровать», «лежал в больнице» без номера и названия,
спокойные истории о жизни со стомой). Обязательно примеры из П-1, П-3…П-9, П-17.
Проверь порядок категорий: сообщение с болью и телефоном должно дать категорию «ostroe».
```

Как проверить: `pytest tests/test_checker.py` — всё зелёное. Попросите Claude показать
вывод `check()` на 10 своих фразах и посмотрите глазами, не перестаралась ли проверка.

## Этап 2. База, отправка сообщений, демо-форум

```
Сделай app/db.py (таблицы из Б4), app/texts.py (тексты из А4.2) и app/main.py:
POST /api/messages, DELETE /api/messages/{id}, GET /forum/{section}, страницу /demo
для выбора одного из трёх тестовых участников (работает только при DEMO_MODE=true).
На странице раздела — форма отправки. Отправка через fetch: при ошибке категорий 3–6
текст остаётся в поле и под ним показывается причина; при категориях 1–2 поле очищается
и показывается экран «Экстренная помощь» или «Неотложный контакт».
При срабатывании пиши в trigger_log только день, категорию и раздел.
Новичок (меньше NOVICE_THRESHOLD опубликованных) — статус pending, иначе published.
Напиши тесты для П-1, П-4…П-9.
```

Как проверить: `uvicorn app.main:app --reload`, откройте `http://localhost:8000/demo`,
пройдите руками П-1, П-4, П-7, П-9.

## Этап 3. Панель модератора и премодерация

```
Сделай app/auth.py и страницы /moderator/login и /moderator/queue по А3, А5, А9 п.3 ТЗ.
Пароли — bcrypt. 5 неверных попыток — блокировка входа на 15 минут.
Модератора создаёт команда: python -m app.create_moderator <логин>.
Отклонение — с причиной из списка А5; текст сообщения при этом обнуляется (NULL).
Каждое действие модератора пиши в moderator_actions.
Автор видит у себя свои pending-сообщения с пометкой «Ждёт проверки модератором»
и отклонённые — «Не опубликовано. Причина: …».
Напиши тесты П-10, П-11.
```

Как проверить: создайте модератора, отправьте сообщение новым участником, опубликуйте и отклоните из панели.

## Этап 4. Жалобы

```
Сделай жалобы по А6 ТЗ: кнопка «Пожаловаться» и галочка «Автору, кажется, очень плохо»
под чужими опубликованными сообщениями; POST /api/messages/{id}/complaints;
уникальность (message_id, user_id); нельзя жаловаться на своё.
На COMPLAINTS_TO_HIDE уникальных жалоб — статус hidden, автор видит «Сообщение скрыто до проверки».
Страница /moderator/complaints: сначала с галочкой, потом по времени; старше COMPLAINT_SLA_HOURS — красным.
Кнопки «Вернуть» и «Удалить с причиной» (текст обнуляется).
Тесты П-12, П-13.
```

## Этап 7. Размещение

```
Сделай Dockerfile и docker-compose.yml (приложение + nginx с HTTPS через certbot).
В nginx log_format без тела запроса. Том для файла БД. Ежедневная резервная копия
базы в отдельную папку с хранением 14 дней (cron в контейнере или скрипт).
Напиши README.md: как запустить на чистом VPS Ubuntu за 10 команд.
```

Сервер — у провайдера с дата-центром в РФ (152-ФЗ). После размещения пройдите таблицу А10 руками
на тестовом сервере и заполните «прошёл / не прошёл» — эту таблицу можно приложить к акту приёмки.

## Что делать, когда юротдел ответит на открытые вопросы (А12)

- О-1 (срок жалобы) → поменять `COMPLAINT_SLA_HOURS` в `.env`.
- О-2 (контакт) → вписать в `app/texts.py`.
- О-4 (марки изделий) → при необходимости новый файл в `rules/` и категория в `checker.py`.
- О-6 (списки) → заменить файлы в `rules/`, прогнать `pytest`.
